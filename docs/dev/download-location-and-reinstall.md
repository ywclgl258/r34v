# 下载位置与重装恢复

当前工作区增量，正式版本仍为 2.2.2 / 36，尚未发布。目标：用户可以把下载切换到卸载后保留的公共目录；重新安装并重新授权后，下载中心自动识别。

## 为什么必须换位置

| 路径 | 卸载后 | 说明 |
| --- | --- | --- |
| `files/`、`cache/`（应用私有） | 全部删除 | 2.2.2 及以前的唯一位置 |
| `Android/data/<包名>/` | 全部删除 | `getExternalFilesDir`，卸载时由系统清理 |
| `Android/media/<包名>/` | 全部删除 | 同上，MediaProvider 一并删除 |
| MediaStore（相册、下载） | 共享媒体保留 | 重装后访问仍需遵守权限和文件归属规则 |
| `/sdcard/R34V/`（直接写） | 保留 | 文件不属于应用，卸载不动；本版采用这一条 |

MediaStore 共享媒体在卸载后保留，见 [Android 官方说明](https://developer.android.com/training/data-storage/shared/media)。本实现采用 `/sdcard/R34V/`，是为了让 Media3 文件缓存、缓存索引、图集及标签文件一起保存在可搬移的真实目录中，并非因为 MediaStore 会自动删除共享媒体。

## 目录结构

```
/storage/emulated/0/R34V/
├── .nomedia                      图页不进系统相册
├── videos/
│   ├── cache/                    Media3 SimpleCache 整体存放
│   │   ├── cached_content_index.exi   编号与缓存键映射，随媒体保留
│   │   ├── <uid>.uid
│   │   └── <分片子目录>/*.v3.exo
│   └── meta/                     每个视频一个标签文件
│       └── <site>_<id>_<quality>-<hash8>.json
└── comics/
    ├── <site>/<sha256(作品id)>/
    │   ├── book.json             详情与页数
    │   ├── links.json            页码↔图源
    │   ├── *.image               原始图页
    │   ├── *.page.json           图页编号与图源元数据
    │   ├── complete              完成标记
    │   └── readme.txt            给用户看的说明（纯文本，任何同步工具都保留）
    └── <site>_<id>-<hash8>.json  漫画标签文件
```

`DownloadCaches` 明确启用 `preferLegacyIndex=true`，把关键缓存索引写到缓存目录的 `.exi` 文件；旧 SQLite 缓存索引会在旧数据库仍在时转换。Media3 的任务数据库仍在私有目录，随卸载消失；下载中心根据标签重建条目，再以真实缓存内容验证完整性。仅保存 `.exo` 和标签而没有 `.exi`，不能保证视频恢复。

## 权限

| Android 版本 | 手段 |
| --- | --- |
| 7.0–9（24–28） | `WRITE_EXTERNAL_STORAGE` 运行时权限 |
| 10（29） | 同上 + `requestLegacyExternalStorage` |
| 11+（30–36） | `MANAGE_EXTERNAL_STORAGE`（设置里的「所有文件访问」） |

三档都收敛成同一个真实 `File` 路径，因为 Media3 的 `SimpleCache` 只接受 `File`，不接受 SAF 的 `Uri`。

**重新安装后需要再允许一次「所有文件访问」。** 权限不是文件属性，不随文件保留。

## 重装后的自动识别

启动先应用待切换位置，再绑定缓存；下载中心异步扫描：

1. 读到 `download_root_*` 偏好为空、但 `/sdcard/R34V` 里存在真实内容（`book.json` 或视频标签文件）→ 自动采纳公共目录。空目录、只剩缓存碎片的不算内容。
2. 同时扫描「公共目录」与「应用内目录」。公共优先，因此迁移前的旧下载不会消失。
3. 逐条校验：视频需要已知总长度、完整连续缓存和真实分片；漫画需要正确的 `complete` 页数、`links.json` 映射、每页元数据与非空目标文件。缺失标为不完整，不当作可离线。
4. 站点已下线、标签文件损坏、页文件缺失都只影响该条，不影响整表。
5. 恢复记录包含经允许目录校验的来源位置，读取不再只查当前下载目录；删除会清理两处同名副本，避免重新扫描后复活。
6. 下载中心增加「重新扫描」入口，随时手动重建。启动时缺少权限的，授权后重新选择迁移或重启再采纳公共库。

**升级用户不会被搬走。** 应用内已有下载时，不会因为公共目录里有残留就自动改位置；改位置必须由用户在设置里明确操作。

## 迁移

设置 → 下载位置 → 改到公共目录：

- Android 7–10 发起存储运行时授权；11+ 打开所有文件访问页面。未授权返回时窗口仍可关闭和重试。
- 先暂停写入，原件保留。视频按缓存键合并到公共缓存，保留目标已有内容；禁止直接拼接两个缓存目录的数字文件或 UID。
- 图集按快照预检：完整公共副本优先保留；两份不同残本会停止迁移；完整私有副本修复公共残本时，完成标记最后写入并再次验证。
- 文件以长度与 SHA-256 校验，复制失败不提交位置；中断临时文件不会冒充正式文件。
- 仅在复制成功后写入 `download_root_pending`。本进程保持原位置且暂停新增/续传，重启时在创建下载管理器之前应用新位置。反向改回应用内同样遵守这一顺序。

## 边界

- 登录状态不随文件保留。`SessionVault` 用 AndroidKeyStore 设备密钥加密，换机或重装后密钥销毁，必须重新登录或重新导入 Cookie。这是安全设计，不是遗漏。
- 公共目录比私有目录脆弱：用户删文件、改名、拔卡、第三方清理都会让索引对不上。扫描把「对不上」当常态处理：跳过坏条目，不崩溃。
- 首次授权把已有私有下载复制到公共目录时会暂时占双份空间，确认无误后再清理私有原文件。
- debug 包与正式包共用同一目录会争用 `SimpleCache` 的锁文件，只用于测试。
