# R34V · rule34video 安卓客户端 · 项目实现步骤蓝图

## 输入与冻结边界

**输入**：
- 已确认事实表（见总设计案「四态决策账本 · 已确认」）；
- `evidence/fixtures/` 10 份真实 HTML（列表 × 6、详情 × 1、登录 × 1、分类 × 1、RSS × 1、embed × 1）；
- 直链 206 实测结论（`Accept-Ranges: bytes`）；
- 本机工具链现状：Flutter 3.44.6 有、JDK 17 有、Android SDK 无。

**冻结边界**（本蓝图内不许自行扩大）：
- 只做 Android 单宿主；Windows 桌面只用于调试烟测，不作交付。
- 只读站点：GET 列表/详情/搜索；登录只到「拿到 Cookie 能读 /my/ 页」为止，不做投票/评论/上传。
- 不做下载、不做投屏、不做 VR。
- 不引入需要付费账号的第三方服务。
- 每个阶段退出条件必须给证据；写代码不算完成。

**执行期约束**：`runtimePersistentBlueprintBudget = 0`——执行中遇到真问题只能开一条临时支线，解决即关，不许长成第二份蓝图。

## 失败回退

真实问题可以建立一层临时问题支线；保存触发证据，解决或确认阻塞后关闭并回到原父步骤。

已预判的三条支线（触发即开，不许扩散）：

1. **P0-支线：首次 CI 构建失败** —— 触发：Actions 里 `构建 APK` 步骤红。处置：按 workflow 里自动输出的「失败排查提示」定位（媒体库下载 / 签名不全 / AGP 冲突三类），修完再推；不在本机装 SDK 兜底。
2. **P1-支线：fixture 与线上不一致** —— 触发：线上页面解析失败但 fixture 通过。处置：重抓该页存为新 fixture、写失败用例、修解析器；修完保留新旧两份。
3. **P4-支线：media_kit 在目标机型异常** —— 触发：真机黑屏/无音/硬解崩溃。处置：先切软解参数验证，再考虑 `video_player` 后备；记录机型与 SoC，不改整体架构。

## 停止条件

遇到以下任一，停下并回到驾驶员，不自行绕过：

- 站点出现 Cloudflare/JS 强挑战，纯 HTTP 客户端拿不到 HTML（需要重新评估整条主线）；
- 直链改为加密（非 `v-acctoken` 明文参数）且客户端无法还原；
- 出现需要绕过登录/付费墙才能看到内容的情形（超出「只读公开内容」边界）；
- 需要引入付费服务或提交密钥到仓库；
- CI 反复失败且已按排查提示试过，仍无法产出可安装 APK。

## 下一道门

代码与文档已就绪，当前卡在「还没有 APK」。驾驶员需要做的是**把仓库推上 GitHub 并触发第一次 CI**：

```bash
git init && git add -A && git commit -m "init"
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

CI 绿 → 下载 `r34v-apk` 装机 → 走「首页 → 详情 → 横屏全屏看 60 秒 → 退出再进能续播」→ 反馈结果。

CI 红 → 贴失败步骤日志，按 workflow 内置的排查提示定位。
