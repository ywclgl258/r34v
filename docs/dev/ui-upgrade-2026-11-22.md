# R34V 界面升级调研

2026 年 11 月 22 日 · 设计提案

## 推荐方向

延续录像带租赁店的品牌。浏览时把注意力交给作品封面，选定作品后用米色片签集中给出标题、进度和下一步动作。黑色画布、R34V 字标和双色斜纹负责识别。暖红只出现在少量状态上，例如导航当前位置和正在推进的进度。

首批改视频首页和发现页。首页先让人看清一部精选作品，看完片名即可播放；往下仍能看到一排新选择。发现页以作品网格为主，用户只需看一行便知道当前分类、排序和筛选。用现有的视频、漫画和写真做设计验收，漫画和写真延续各自的完整封面比例。

## 现状与依据

基线为 `348d82f` 的产品界面。使用 Android 16 模拟器、1080 × 2400、420 dpi（约 411 dp 宽）和默认系统字体，以中性测试数据实拍。首页、三类来源、下载中心、播放器和切站相关的五项原生设备用例通过。目录、播放器和抽屉均使用现有组件。静态截图经独立走查。

## 如何借鉴 Netflix

Netflix 2026 年移动端官方画面上，首屏只有一个占主导的海报，片名和行动集中在封面下部。播放用高对比浅色按钮，片单操作相对安静，内容类别在封面之外。R34V 可借用这种层级，将视频精选从左右等权的封套改为封面大于信息区的构图，并保留自己的字标、暖色片签、目录结构和媒体三分法。参考 [Netflix 2026 移动端发布与首页官方画面](https://about.netflix.com/en/news/introducing-exciting-new-ways-to-find-and-enjoy-your-next-favorite-on-mobile)。

「My Netflix」的产品做法是为续看、收藏和下载提供一个明确的个人入口。R34V 已有「我的」与「片库」，这里可借用的是任务优先级。「我的」让用户接着看或读，「片库」让用户管理保存的内容。当前方案通过现有五项导航完成这些任务。「发现」使用封面与筛选改善决策速度，自动播放短片不进入本批。参考 [Netflix 对个人入口的官方说明](https://about.netflix.com/en/news/introducing-my-netflix-a-one-stop-shop-for-series-and-movies-you-want-to)。

```text

                                   分类            排序      筛选

[ 播放 ]  [ 稍后看 ]  轮播控制       后续作品

第一排海报
首页   发现   搜索   片库   我的    首页   发现   搜索   片库   我的
```

- **构图。** 视频精选先试 16 dp 页边距、240–268 dp 的封面与信息总高度，按实际首屏调整。白或浅米色只强调播放键。标题约 24–26 sp、最多两行。榜单保留一眼可读的名次，封套轮廓在普通卡片上减轻。轮播的暂停状态和当前页继续可见。
- **媒体差异。** 视频横封面允许按容器裁切，漫画与写真完整展示。首屏精选无封面时直接显示有标题的深色占位，封面失败用相同尺寸。站点缺少榜单时，用已加载的真实内容继续首屏布局。
- **动作和反馈。** 播放从精选直接进入播放器。稍后看在原处显示选中反馈，使用现有状态。发现的非默认筛选可在原位清除，更新后保留站点隔离。按压沿用现有轻微下沉，选中过渡可用短淡变，系统关闭动画时直接切换。

## 实施顺序与验收

1. **首页和发现。** 先在 `ComposeCinema.kt` 调整精选、榜单和底栏，再在 `ComposeBrowse.kt` 调整筛选与网格。只在受影响的路径新增样式参数，避免首批修改全部 `MediaCard` 调用者。
2. **「我的」和下载中心。** 下一批统一真实进度文案。下载行按状态提供一个主要动作，比如继续、重试或离线打开。完整状态与失败原因仍可查看，批量重试和已保存内容继续走原入口。
3. **播放器与阅读器。** 最后统一播放控件及详情信息块。在亮帧和暗帧上检查文字对比，同时核对视频播放手势、清晰度菜单、阅读器全屏和返回保存。

首批上线前用标准手机和默认系统字体取前后截图。基线场景包括有数据、无榜单、封面失败、中文长标题和视频、漫画、写真切站。首屏可见精选片名、播放操作与下一片架的首排部分。所有主要动作的触控区至少 48 dp，选中态同时有语义或形状提示。刷新后、切站和筛选时用现有作品锚点回归检查位置，列表继续使用稳定作品键。参考 [Compose 触控区域](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)与 [Lazy 布局项目键](https://developer.android.com/develop/ui/compose/lists#item-keys)。

功能回归优先用 `CinemaUiTest`、`LiquidMediaUiTest`、`FeedPositionUiTest`、`SiteSwitcherUiTest` 及 `UnifiedDownloadsTest` 中的关联用例。之后拍同一组测试图，复核首屏对齐、正文对比与关键操作路径。视觉改动引入的封面请求与滑动开销用同一设备、同一素材与原版对照。

## 第一批实施结果

视频首页的精选画面占满封套宽度，片名、播放和稍后看排列在下方。人气榜海报以名次和作品名为主，标题留两行高度，同排名次对齐。发现页保留一行分类与排序，漫画来源在同一行提供语言入口。非默认条件显示摘要和清除操作。刷新保留直接入口。普通封套用深色标题区与轻描边，漫画和写真仍完整显示封面。

用 `CinemaUiTest#immersiveHeroPlaylistAndHorizontalShelves` 在 Android 16 标准手机模拟器采集同一套素材的首页和发现页前后图。开发机的对照图在 `dist/ui-upgrade-phase1-2026-11-22/`，文件为 `home-before-after.jpg` 与 `discover-before-after.jpg`。独立截图走查指出名次随标题行数跳动、下拉入口不够显眼，最终版用两行标题区与低对比下拉底色修正。

Android 16 通过 13 项本批相关用例，含无榜单、空封面、长篇中文标题，切站、分类、排序、语言、清除与刷新。另跑两阶段进程测试，分别记录作品、强制结束应用进程，再从新进程验证首页恢复同一片架作品，发现恢复第二页作品。Android 7 补跑 5 项关键用例。332 项 JVM 通过，Debug Lint 为 0 错误、27 条警告。截图来自本地测试数据，未作线上站点素材或滚动性能的量化比较。
