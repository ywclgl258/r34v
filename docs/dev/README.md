# 开发过程文档

这里的文件是**开发过程中的工作文档**，不是给使用者看的。想了解这个 App 怎么用、有什么功能，看根目录的 [`README.md`](../../README.md)。

| 文件 | 是什么 |
|---|---|
| `总设计案.md` | 项目目标、技术选型理由、决策记录、首版范围、后续方向 |
| `项目实现步骤蓝图.md` | 分阶段的实施计划与验收标准 |
| `NEXT.md` | 续接记录：已确认的事实、当前进度、未验证项、下一步 |
| `播放页手势与页面合并-问题记录.md` | 播放页手势全部失效的根因、详情/播放拆分回归、横滑调速设计，以及未验证项 |
| `.tavernweave/` | 上述文档的编排清单（状态、决策项、验收门） |

## 为什么保留这些

不是流程洁癖，是实际有用的两件事：

1. **`NEXT.md` 记录了「哪些验证过、哪些没验证」**。比如播放器在真机上从没跑过、`v-acctoken` 的确切有效期未知——这些写在里面，避免以后误以为「已经没问题了」。
2. **`总设计案.md` 记录了技术选型的理由**。为什么不用 WebView 套壳、为什么解析层必须用真实页面快照做测试、为什么缓存用整段下载而不是分片——这些都是踩过坑之后定下来的，忘了就会重踩。

## 维护方式

改代码时同步更新 `NEXT.md` 的「最近证据」和「开放风险」，其他两个文件只在范围或方向变化时改。

`总设计案.md` 和 `NEXT.md` 里的路径引用都指向仓库根目录（如 `test/fixtures/`、`lib/`），实际文件在根目录，不在这里。
