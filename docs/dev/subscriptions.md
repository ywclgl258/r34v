# 标签订阅

在 2.2.3 之后新增。用户可以订阅标签，订阅页只显示已订阅标签下的作品，顺序可自定义，订阅与排序都按站点独立。

## 使用方式

- **订阅**：标签索引里每个标签右侧有“订阅”按钮；任意标签页顶部也有“订阅标签”。两处都能取消。
- **订阅页**：顶栏书签图标进入，或从空状态里的“浏览标签”进入。
- **排序**：订阅页顶部下拉选择，按站点记忆。
- **管理标签**：订阅页 → 管理标签，可上移、下移、取消订阅。列表顺序就是排序依据。

## 三种排序

| 选项 | 行为 |
| --- | --- |
| 订阅顺序（默认） | 按标签分组，组的先后就是你排的顺序；同一作品只出现一次，落在第一个包含它的标签下 |
| 混合交替 | 各标签轮流取一条，避免一个标签占满整屏 |
| 名称排序 | 先合并去重，再按标题排序（大小写不敏感，同标题按 id 兜底） |

合并规则写在 `SubscriptionMerge` 里，是纯函数，不碰网络，因此可以直接单测。

## 站点隔离

订阅存在 `"<站点id>:subscriptions_v1"`，排序存在 `"<站点id>:subscription_order_v1"`。同一个 slug 在两个站是两个独立订阅：在 Rule34Video 订阅 `sample` 不会让 E-Hentai 也多一条，取消一边也不影响另一边。

## 容错

- 一个标签取不到内容时，其余标签照常显示，顶部点名是哪个标签失败（`1 个标签暂时取不到内容：XXX`）。
- 订阅为空时不发请求，只显示引导。
- 已屏蔽的标签（现有屏蔽词）依然生效，订阅页也走同一层过滤。
- 标签本身没有内容时，该组直接不出现，而不是留一个空标题。

## 改动

| 文件 | 作用 |
| --- | --- |
| `data/Subscription.kt` | 数据结构、排序枚举、`SubscriptionMerge` 合并与排序 |
| `data/LibraryStore.kt` | `subscriptions` / `toggleSubscription` / `moveSubscription` / `subscriptionOrder`，均按站点 |
| `data/Network.kt` | `Repository.subscriptions()`：并发取各标签；`Repository` 现持有 `LibraryStore` 以便过滤屏蔽词 |
| `ui/ComposeSubscriptions.kt` | 订阅页、管理标签对话框、`SubscribeAction` 按钮 |
| `ui/ComposeBrowse.kt` | 标签页与标签索引上的订阅入口 |
| `MainActivity.kt` | `subscriptions` 路由、顶栏入口、`toggleSubscription` / `openTag` |

- Lint 无错误。

## 未覆盖

- 真实站点标签页的抓取只经既有适配器，没有新增站点协议；四个漫画站与三个视频站的标签行为仍依赖各自原有解析。
- 订阅数量很大时（几十个标签）会同时发起同样多的请求，目前没有做分批限流；实际使用中建议保持在个位数。
