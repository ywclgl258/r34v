# 播放缓冲与链路自适应（2026-11-12）

版本基线：2.7.1 / 48 的工作树。本轮只交付开发包与回归证据，未递增 versionCode、未构建或发布正式包。

## 问题

用户报告 rule34video 视频站“缓冲非常慢”。实测（14:40–15:00，本机系统代理 127.0.0.1:7897）：

| 项目 | 实测 |
|---|---|
| 列表页 / 详情页 | 178–226 KB，TTFB 0.47–0.51 s，总 1.0–1.25 s（正常） |
| 媒体地址 | 302 到 `eu-cdn04-prem.boomio-cdn.com`，多一跳 |
| 720p 成片 | 13,190,613 B / 42.987 s ≈ **2456 kbps** |
| CDN 直连降速 | **219 / 255 / 361 KB/s**，8 连接并行也只有 413 KB/s |
| 同一 CDN 走代理 | 1.0–2.1 MB/s |

结论：**不是解析、DNS 或 token 问题，是链路带宽（约 2.0 Mbps）刚好压在 720p 码率（2.45 Mbps）之下，而播放器既不按实测带宽选档、也没有任何降档出口。**

排除项：`moov` 在文件第 32 字节（faststart 正常）；媒体 302、206、`Accept-Ranges: bytes` 均正常；`v-acctoken` 为打开详情页时现取，60 分钟窗口；DNS 0.07 ms。

## 改动

### 1. 起播按实测带宽选档 — `playback/StreamSelection.kt` + `PlayerActivity.chosenStream`

- 参考码率表：360p 800 / 480p 1200 / 720p 2500 / 1080p 4500 kbps；无法从标签取高度（“原画”“自动”）按 2500 kbps 计，不当成零成本。
- 预算 = 实测带宽 × 0.7，留出重传、并发与抖动余量。
- **带宽未知时完全沿用旧行为**（用户设置优先），诊断失败不会悄悄改画质。
- 偏好档喂得动就用偏好档；喂不动取“不高于偏好档且仍在预算内”的最高档；全都不在预算内仍给最低档而不是报错。
- **永不自动升到用户设置之上**。

### 2. 卡顿自动降档 — `playback/StreamSelection.kt:StallPolicy` + `PlayerActivity.maybeDowngrade`

三个信号任一成立就退一档：起播阶段缓冲 ≥ 6 s（位置 < 5 s）、播放中单次缓冲 ≥ 8 s、30 s 窗口内累计 3 次缓冲。整部片子最多自动降两档，两次降档间隔 ≥ 20 s，保留播放位置与播放状态，并在画面上明说“网络跟不上 720p，已自动降到 480p”。

### 3. 缓冲窗口跟着载荷走 — `StreamSelection.bufferPlan`

| 场景 | min/max/播放/再缓冲 |
|---|---|
| 高码率（≥4200 kbps） | 8000 / 40000 / 500 / 800（近旧值） |
| 720p 且链路宽裕 | 4000 / 15000 / 500 / 1000 |
| 低码率或链路吃紧 | 2500 / 12000 / 500 / 1000 |

旧值是全局 `8000 / 50000`：720p 的 8 秒起播缓冲 = 2.4 MB，250 KB/s 下要 9.8 秒才出画。`LoadControl` 建好后不能改，因此缓冲窗口变化时重建引擎（新引擎就位后才释放旧的，避免在旧引擎的回调里把它抽走）。

### 4. 流式缓存写入可关，默认关 — `PlaybackStore.sourceFactory(cacheStreaming)` + 设置项

流式读路径不再同步写 512 MB 临时缓存；`settings_v1_stream_cache` 打开后恢复旧行为。已下载内容不受影响。备份白名单已同步（`LibraryBackup.backupBooleans`）。

### 5. 自动下载改到首帧之后 — `PlayerActivity.startPendingAutoDownload`

以前拿到播放地址就 `add()`，下载并行 2 个任务立刻和播放抢同一条链路。现在首帧就绪后才入队，只做一次。

### 6. 网络诊断加入媒体测速 — `playback/MediaProbe.kt` + `playback/PlaybackDiagnostics.kt`

旧诊断只请求首页 HTML，因此永远显示“实时请求成功”，无法解释缓冲。现在测：首页 → 详情页取播放地址 → 对用户偏好档做 1 MB Range 采样，报出实测 kbps、该档所需码率与“这条链路适合哪一档”。

## 验证

- JVM：`StreamSelectionTest` 15 项，覆盖码率映射、未知带宽不动画质、不越权升级、极慢链路兜底、降档走位、缓冲窗口分档与三种卡顿信号。
- 完整 JVM 回归与 Debug 构建结果见本轮末尾报告。

## 未验证 / 边界

- 自动降档与缓冲窗口的真实弱网行为需在真机 + 限速网络下复测；本轮只验证了纯策略与编译。
- 码率参考表是典型值，不是站点给出的真实码率；站点若改编码，判断会偏移一档。
- 代理侧 1.0–2.1 MB/s 的实测说明“走代理够用”，但代理本身的稳定性不在应用控制范围内。
