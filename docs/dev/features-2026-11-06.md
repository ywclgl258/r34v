# 2.4 功能实施与验收

用户在 2026-11-06 确认上一轮提案“全做”。首批范围为九项：个人首页、保存搜索、合集连续观看／阅读、浏览器分享接收、离线片单准备、智能片单、阅读缩略图总览、平板／折叠屏列表详情、本地 CBZ／ZIP／图片目录导入。隐私体验仍排除；不推送、不发布。

沿用 2.3.0 / 41 的本地未提交改动和已确认黑底内容优先设计。正式更新目标 2.4.0 / 42，按统一签名流程交付标准与 Android 7/8 原 2.0.0 专用兼容包。

实施按三个阶段推进，不增设蓝图层级：

1. 数据与媒体路由：保存搜索／智能片单、可恢复的连续上下文、本地媒体独立身份与有界导入。退出条件为数据迁移、备份兼容与本地导入测试通过。
2. 原生入口与页面：个人首页、片库书架与筛选、大屏列表详情、外部链接、离线准备和缩略图。退出条件为主要入口可观察、失败恢复与原生回归通过。
3. 最终验证与打包：定向测试、Lint、手机／大字体／横屏／大屏检查、正式双包和分段 API 证书验证。只报告实际取得的证据。

本轮实施与本地验收完成。九项功能及三类媒体 UI 改版已接入原生页面；165 项 JVM、默认视口 36 项整组设备回归通过。独立 UX 走查后追加本地缺失文件恢复补验，合并为 37 项不同设备用例通过。320dp / 200% 字体、短横屏和 1280dp 大屏已验证。标准正式包与旧 2.0.0 兼容包完成签名、包信息和覆盖安装核验，完整记录见 [交付核验](verification-2.4.0.md)。NEXT.md 保持唯一当前续接指针。

独立代码检查修复四项：扫描恢复作品改用缓存键与原存储根路由，避免已离线却走网络或登录门禁；搜索方案来源列表加入重建状态；未知智能片单规则在恢复前拒绝；合集加入时间与完成状态更新时间分别保存，旧备份兼容回退。

设备验证期间确认 Windows 上的 Emulator 37.2.13 headless 进程存在 0xc0000005 异常退出（Windows Application Error 记录，非应用 Java 崩溃）。新队列 UI 用例在首项等待加载时验证手动跳转，实际离线视频解码由单独的扫描恢复回归验证；不将 UI 跳转当作解码成功，也不报告性能结论。模拟器使用软件图形与关闭主机硬件解码的启动参数，未修改系统或 SDK 配置。

路由回执：orchestrate-project-blueprint；Library snapshot 2026-08-18，已读取 ST-A0；Android CLI 已安装。用户“全做”已确认提案全部范围，无需再次询问设计许可。
