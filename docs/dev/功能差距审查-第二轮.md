### 排行榜

站点有两个**格式完全不同**的榜单，这点走了一些弯路才弄清：

**角色榜**（`/top-characters/`）是两层结构：

1. 第一层列**作品/游戏**（genshin-impact、overwatch…），每个带角色数
2. 点进去才是该作品的角色榜，`li.cs-row` 行式：

```html
<li class="cs-row">
  <span class="cs-row__rk">1</span>      名次
  <a href="/tags/aether-genshin-impact/"> Aether
  <small class="cs-row__t">aether (genshin impact)</small>
  <b>6.6M</b>                            播放量
  <em>Favourites</em>26K                 收藏
  <em>Videos</em>70                      视频数
```

注意角色链接指向 `/tags/`——**站内角色就是 tag**。

**作者榜**（`/top-model/`）没有独立的正文区：

- 它渲染的就是侧栏那块 `Top Artists`，普通列表页侧栏里也有同样一块
- 所以解析器按 **`Top Artists` 标题定位**，不按页面路径
- 同一页面里这块可能出现两次（主体侧栏 + `sidebar_pages`），名次都从 1 开始，必须按 slug + 名次双重去重
- 结构是 `a.item` 卡片：名次 + 头像 + 名字 + 好评率

实测数据：角色榜 25 条（genshin）、作者榜 10 条。

## 二、TYPE 标记的真实情况

驾驶员截图里的 TYPE（Straight / Gay / Futa / Music / Iwara）是**封面角标**，不是筛选器：

```html
<div class="futa">Futa</div>
```

结论：

- class 全叫 `futa`（样式名），**文本才是类型**
- 没有链接，不是可点的筛选入口
- `?type=futa` 无效（总数不变）
- `/futa/`、`/type/futa/` 全部 404

所以它只能**显示**，不能用来筛。目前**尚未实现**——需要驾驶员确认要不要加这个角标。

采样 6 页最新列表，只出现 `Futa`（16 次）和 `Gay`（1 次），
`Straight`/`Music`/`Iwara` 极罕见。这也说明它不是主要分类维度。

## 六、一个过程教训

这轮我三次判断错了页面结构：

1. 以为 `/characters/` 是角色索引 → 实际 404
2. 以为 `/top-model/` 是扁平榜单 → 实际要看 `Top Artists` 区块
3. 以为「有 `.position` 就是榜单」→ 实际列表页侧栏也有

每次都是把**测试断言建立在猜测上**才发现的。
所以这轮补的 19 项榜单测试里，特意包含「列表页也能解析出 Top Artists 区块」这一条——
它锁住的是「按标题定位、不按页面路径」这个真实行为，防止以后有人"优化"成路径判断。
