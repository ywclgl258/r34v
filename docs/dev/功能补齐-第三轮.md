## 一、本轮四项

### 1. TYPE 角标

原站的封面角标：

```html
<div class="futa">Futa</div>
```

**关键坑**：class 名**全部**叫 `futa`（样式名），真正有区分度的是文本。
按 class 匹配会把所有类型都识别成 Futa。

所以解析器按「容器内的短文本 + 白名单」取值，不用 class：

```dart
const known = {'straight','gay','futa','music','iwara','lesbian','trans','other'};
```

实测最新一页 23 个视频里 5 个带角标，全是 `Futa`，其余为空——说明没误判。

显示上放在封面左下，HD 角标之上（两者位置会撞），用琥珀色和 HD 的白色区分。

> 它只能显示，不能筛选。`?type=futa` 和 `/futa/` 都实测无效。

### 2. 下载

详情页每档清晰度一个下载直链：

```html
<a class="tag_item tag_item_download"
   href="…/x_1080p.mp4/?v-acctoken=…&download=true&download_filename=mario_1080p.mp4">
```

实现要点：

| 项 | 处理 |
|---|---|
| 清晰度 | 从 URL 或文件名里取；**注意最低档是 `_360.mp4` 没有 p** |
| 文件名 | 用 `download_filename` 参数，比拿标题拼可靠 |
| 落盘 | 优先系统下载目录，拿不到退回应用私有目录（安卓分区存储限制） |
| 半截文件 | 写 `.part`，校验字节数后改名 |
| 与缓存的关系 | **分开**：缓存是应用私有、为快速重播；下载落到用户能访问的位置 |

踩过的 bug：只匹配 `_Np.` 会漏掉 360 档，回退到用链接文本后 label 变成
`MP4 360p2 MB`（把文件大小也吃进去了）。已修正并写了测试。

### 3. Uploaded（上传者）

这是这轮最有价值的发现——站点有**两套作者体系**：

| 页面 | 含义 | 例子 |
|---|---|---|
| `/models/<slug>/` | **作者/艺人**（谁画的） | `doll-house` |
| `/members/<数字id>/` | **上传者**（谁传的） | `AbstractAlex` (335916) |

实测 `video-4703101`：上传者是 `AbstractAlex`，作者是 `doll-house`——**完全不是同一个人**。
之前只做了作者，漏了上传者。

详情页现在单列一行「上传者」。

### 4. 评论（只读）

解析 `#tab_comments` 里的评论列表，显示作者、时间、正文、头像。

- 没有评论时返回空列表，不当作解析失败
- 不做发表（需要登录 + 表单，且不属于只读浏览的范畴）

## 三、验证方式的一个限制

这轮想给新 UI 出一张离线截图（用冻结的真实页面渲染），发现：
**Flutter 测试环境不加载 pubspec 里声明的字体**，截图里中文全是方块。
`FontLoader` 手动加载也没能在 `toImage` 前生效。

结论：测试环境的截图只能验证布局结构，验证不了文字渲染。
文字要看 Web 预览或真机。这条限制记在这里，避免下次又花时间重复试。

另外这轮抓站点太密集，触发了限流（403/502）。后续验证要拉开间隔。

## 四、测试

新增 30 项（TYPE 5 项 + 下载 6 项 + 上传者 3 项 + 评论 2 项 + 详情 UI 5 项 + 榜单 9 项）。

总计 **188 项通过**，`flutter analyze` 零 issue，`flutter build web` 通过。

其中几条测试是专门用来钉住「反直觉的事实」的：

- 类型必须来自白名单，不能按 class 名匹配（否则全变 Futa）
- 下载 label 必须是 `720p` 这种，不能带 `MB`（踩过）
- 上传者不等于作者（若相等说明抓错字段）
- 列表页也能解析出 Top Artists 区块（因为它侧栏真有，不是 bug）
